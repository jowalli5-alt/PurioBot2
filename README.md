# PurioVPN Bot — инструкция по запуску

Бот для продажи VPN-подписок в Telegram с интеграцией Remnawave (панель 3.2.3,
выдача доступа) и Platega (приём оплаты через СБП). Полностью готов к запуску —
нужно только вставить свои токены и ключи.

## Что уже реализовано

- Обязательная подписка на канал `@PurioVPN` перед использованием бота (реферал
  не теряется, даже если пользователь ещё не подписан на момент перехода по ссылке)
- Главное меню: Профиль, Баланс, Подписка, Рефералы, Поддержка, Наш канал
- Раздел «Поддержка»: создание тикета (диалог прямо в боте), прямой контакт,
  политика конфиденциальности и пользовательское соглашение (по ссылке из `.env`)
- Тикет-система: пользователь пишет вопрос → тикет приходит всем админам с
  кнопкой «Ответить» → ответ админа автоматически приходит пользователю в чат
- Админ-панель (видна только ID из списка админов): выдать баланс, выдать/забрать
  подписку вручную по ID, найти карточку пользователя по ID (баланс, подписка,
  статистика рефералов), написать одному пользователю по ID, рассылка всем,
  тикеты, список пользователей, история платежей, список серверов
  (кол-во пользователей / трафик / пинг) с мониторингом, статистика/логи
- Раздел «💰 Баланс» (отдельный пункт главного меню): текущий баланс и
  пополнение — пользователь сам вводит любую сумму в рублях (в заданных
  границах) и оплачивает через Platega (СБП)
- Подписка: статус, покупка/продление тарифов (1, 2, 6, 12 месяцев) — списывается
  с баланса, автоматическая выдача доступа через Remnawave API. Ссылка на
  подписку сохраняется в БД и всегда доступна в разделе «🔑 Подписка», даже
  после выхода из бота и повторного захода
- Рефералка: ссылка вида `t.me/бот?start=ref_ID`, 3 дня подписки бесплатно
  (с реальной выдачей доступа в Remnawave) за первую покупку реферала +
  7% от суммы **каждой** его покупки подписки деньгами на баланс — работает
  независимо от того, откуда взялся баланс реферала (пополнение через
  Platega или выдан админом вручную). У каждого пользователя два счётчика:
  всего приглашено / сколько из них купили подписку — видно и самому
  пользователю в разделе «Рефералы», и админу через «🔎 Найти пользователя»
- База активных подписок: отдельная таблица `subscriptions` хранит ссылку,
  тариф и дату истечения подписки каждого пользователя; истёкшие записи
  автоматически вычищаются фоновой задачей раз в час (профиль пользователя —
  баланс, рефералка, история — при этом не удаляется)
- Логирование: каждый `/start`, покупка, пополнение, тикет, начисление — пишется в базу

## Шаг 1 — устанавливаем зависимости

Понадобится сервер с Python 3.11+ (можно на том же VPS, где стоит Remnawave —
бот должен работать круглосуточно, поэтому держать его на домашнем ПК не стоит).

```bash
cd purio_vpn_bot
python3 -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Шаг 2 — создаём бота в Telegram

1. Напиши [@BotFather](https://t.me/BotFather) → `/newbot`
2. Придумай имя и юзернейм (должен заканчиваться на `bot`)
3. Скопируй токен вида `123456789:AAF...`

## Шаг 3 — настраиваем .env

```bash
cp .env.example .env
nano .env
```

Заполни:

```
BOT_TOKEN=токен_из_botfather
BOT_USERNAME=юзернейм_бота_без_собаки
CHANNEL_USERNAME=@PurioVPN
CHANNEL_LINK=https://t.me/PurioVPN
SUPPORT_USERNAME=@твой_саппорт

# Ссылки на документы (необязательно, но желательно):
PRIVACY_POLICY_URL=https://ссылка_на_политику_конфиденциальности
TERMS_OF_USE_URL=https://ссылка_на_пользовательское_соглашение
```

Если `PRIVACY_POLICY_URL` / `TERMS_OF_USE_URL` оставить пустыми — бот всё равно
покажет кнопки в разделе «Поддержка», но откроет запасной текст-заглушку вместо
перехода по ссылке. Как только вставишь реальные ссылки — кнопки станут вести
прямо на них.

**Важно:** бота нужно добавить **администратором в канал `@PurioVPN`**
(достаточно доступа к списку участников), иначе он не сможет проверять
подписку пользователей.

Админы бота уже прописаны в `config.py`:
```python
ADMIN_IDS = {6243421380, 6848143236}
```
Если нужно добавить/убрать админа — меняешь эти цифры прямо в файле.

## Шаг 4 — подключаем Remnawave (панель 3.2.3)

1. Зайди в панель Remnawave → **Settings → API Tokens** → создай новый токен
   с правами на управление пользователями
2. Найди UUID нужного сквада (группы нод, к которой будешь давать доступ) —
   он виден в разделе **Squads** в панели
3. Заполни в `.env`:

```
REMNAWAVE_BASE_URL=https://panel.твой-домен.com
REMNAWAVE_API_TOKEN=токен_из_панели
REMNAWAVE_SQUAD_UUID=uuid_сквада
```

`REMNAWAVE_BASE_URL` указывай **без `/api` на конце** — библиотека сама
подставляет нужный путь.

Бот использует пакет `remnactual` (форк официального SDK Remnawave),
версия которого в `requirements.txt` (`remnactual==3.2.3`) сверена
**побайтово** с backend-contract именно панели 3.2.3 — той версии, что
у вас установлена. Если в будущем обновите панель — проверьте таблицу
совместимости версий на https://pypi.org/project/remnactual/ и поправьте
версию пакета в `requirements.txt`.

### Проверка перед запуском в продакшн

В комплекте есть файл `test_remnawave.py` — проверяет связку с панелью
напрямую, без Telegram, и сразу покажет точную причину ошибки, если
что-то не так с токеном/URL/UUID сквада:

```bash
python test_remnawave.py
```

Если увидишь `✅ УСПЕХ!` и ссылку — значит всё настроено верно.

## Шаг 5 — подключаем приём оплаты (Platega)

1. Оформи подключение на [platega.io](https://platega.io) — для интеграции
   достаточно почты и базовых сведений о бизнесе, ИП/ООО не обязательны
2. После модерации в личном кабинете, на странице **Настройки**, возьми
   `MerchantId` и `API ключ` (Secret)
3. Заполни в `.env`:

```
PLATEGA_MERCHANT_ID=твой_merchant_id
PLATEGA_SECRET=твой_секретный_ключ
PLATEGA_RETURN_URL=https://t.me/PurioVPN
```

Как это работает у пользователя: в разделе «💰 Баланс» он жмёт «Пополнить
баланс», вводит любую сумму в рублях (в границах `TOPUP_MIN_AMOUNT` /
`TOPUP_MAX_AMOUNT` из `.env`) → бот создаёт транзакцию в Platega (способ
оплаты — СБП по QR) → присылает кнопку "Оплатить" → после оплаты
пользователь жмёт "Проверить оплату" в боте, либо бот сам обнаружит оплату
в течение 20 секунд — фоновая проверка уже встроена, ничего дополнительно
настраивать не нужно.

Пока `PLATEGA_MERCHANT_ID`/`PLATEGA_SECRET` не заполнены, при нажатии на
пополнение бот честно пишет пользователю "оплата в разработке" — баланс
тогда можно начислять вручную через админ-панель (💰 Выдать баланс).

## Шаг 6 — тарифы и суммы (при желании поменять)

Открой `config.py`, там всё в одном месте:

```python
TOPUP_MIN_AMOUNT = 50      # минимальная сумма пополнения, руб.
TOPUP_MAX_AMOUNT = 100000  # максимальная сумма пополнения, руб.

TARIFFS = {
    30: 149,    # 1 месяц
    60: 250,    # 2 месяца
    180: 699,   # 6 месяцев
    365: 1290,  # 12 месяцев
}

REFERRAL_BONUS_DAYS = 3   # дней подписки за первую покупку реферала
REFERRAL_PERCENT = 0.07   # 7% от суммы каждой покупки подписки рефералом
```

Меняешь цифры — сразу применяется при следующем запуске бота. Не забудь, что
для `TARIFF_LABELS` (тексты кнопок) и `TARIFFS` (дни → цена) значения должны
совпадать — их два словаря специально, чтобы можно было красиво подписать
кнопку отдельно от цифры дней.

## Шаг 7 — запуск

```bash
python bot.py
```

Если всё настроено верно, в консоли появится `Бот запущен`. Напиши боту `/start`
в Telegram и проверь, что всё работает.

### Чтобы бот работал постоянно (не отключался при закрытии терминала)

Создай systemd-сервис:

```bash
sudo nano /etc/systemd/system/purio-bot.service
```

Вставь (поправь пути под свои):

```ini
[Unit]
Description=PurioVPN Telegram Bot
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/root/purio_vpn_bot
ExecStart=/root/purio_vpn_bot/venv/bin/python bot.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Запусти и включи автозапуск:

```bash
sudo systemctl daemon-reload
sudo systemctl enable purio-bot
sudo systemctl start purio-bot
```

Смотреть логи:

```bash
sudo journalctl -u purio-bot -f
```

## Как пользоваться админ-панелью

Зайди в бота под одним из ID администраторов → в главном меню появится
кнопка **⚙️ Админ-панель**:

- **💰 Выдать баланс** — вводишь Telegram ID пользователя, потом сумму
  (можно отрицательную, чтобы списать)
- **🔑 Подписка (выдать/забрать)** — «➕ Выдать подписку»: вводишь ID и
  кол-во дней, бот выдаёт/продлевает доступ через Remnawave и уведомляет
  пользователя; «➖ Забрать подписку»: вводишь ID — доступ в Remnawave
  отключается, подписка в боте аннулируется
- **🔎 Найти пользователя (ID)** — вводишь Telegram ID, бот показывает карточку:
  баланс, статус и ссылку подписки, кто пригласил, и реферальную статистику
  (сколько всего приглашено / сколько из них купили подписку / сколько
  заработано с рефералов)
- **✉️ Написать одному (ID)** — вводишь Telegram ID и текст, бот отправит
  сообщение только этому пользователю (не рассылка)
- **📣 Рассылка всем** — вводишь текст, бот разошлёт его всем,
  кто хоть раз нажимал `/start`
- **🎫 Тикеты** — список открытых обращений от пользователей; открой тикет,
  нажми «Ответить» и пришли текст — он сразу уйдёт пользователю в чат.
  «Закрыть тикет» убирает его из списка открытых
- **👥 Пользователи** — список всех с балансом, датой окончания подписки
  и тем, кто кого пригласил, с пагинацией
- **🧾 История платежей** — список всех платежей (Platega) с ID транзакции,
  ID пользователя, суммой, статусом и датой, с пагинацией
- **🖥 Серверы** — список нод Remnawave: статус (онлайн/офлайн), кол-во
  пользователей, трафик и пинг (замеряется живым TCP-подключением к ноде),
  плюс общий блок мониторинга (пользователей онлайн/всего, суммарный
  трафик). Кнопка «🔄 Обновить» пересчитывает данные заново.

  ⚠️ Названия методов/полей Remnawave SDK в `remnawave_client.py`
  (`get_all_nodes`, `users_online`, `traffic_used_bytes` и т.д.) взяты по
  типовой структуре API — сверь их с реальной версией `remnactual`,
  установленной у тебя, и поправь при необходимости (в коде оставлены
  комментарии, что именно проверить)
- **📊 Статистика** — общее число пользователей + последние 15 действий
  (логи: старты, покупки, пополнения, тикеты, начисления бонусов)

### Как работает тикет-система у пользователя

1. Пользователь заходит в «Поддержка» → «🎫 Создать тикет» → пишет вопрос
   одним сообщением
2. Тикет создаётся в базе, и **всем** админам из `ADMIN_IDS` сразу приходит
   уведомление с текстом вопроса и кнопкой «Ответить»
3. Любой админ жмёт «Ответить», пишет текст — ответ мгновенно уходит
   пользователю в личку от бота
4. Пока тикет не закрыт вручную, он остаётся в списке «🎫 Тикеты» в админке
   (🆕 — ещё без ответа, 💬 — уже отвечен)

## Важное про Fragment/настройки клиента

Если хочешь, чтобы пользователь получал не просто голую subscription-ссылку,
а сразу с настроенным обходом DPI (Fragment `tlshello`) — это настраивается
не в боте, а в самой панели Remnawave, в разделе **App Config Profiles /
Custom subscription templates** для приложения Happ. Как только это будет
один раз настроено там — все ссылки, которые бот получает через
`provision_subscription()`, автоматически будут отдавать клиенту уже готовый
профиль с фрагментацией.

## Обновление бота с сохранением БД

База данных лежит в `data/bot.db` — эта папка (и `.env`) прописаны в `.gitignore`,
поэтому `git pull` их никогда не увидит и не перезапишет.

Обновление одной командой:

```bash
./update.sh
```

Скрипт сам: сделает бэкап БД в `backups/`, подтянет изменения из GitHub,
обновит зависимости и перезапустит systemd-сервис `purio-bot` (если он есть).

**Если у тебя уже был старый деплой**, где `bot.db` лежал в корне проекта и,
возможно, случайно закоммичен в git — один раз выполни:

```bash
git rm --cached bot.db          # убрать файл из индекса git (сам файл не тронется)
mkdir -p data && mv bot.db data/bot.db   # перенести в новую папку
git add .gitignore
git commit -m "chore: move db out of git tracking"
```

После этого `DB_PATH=data/bot.db` в `.env` (уже стоит по умолчанию в
`.env.example`) — и обновления из GitHub больше никогда не тронут базу.

## Структура проекта

```
purio_vpn_bot/
├── bot.py                 — точка входа, запуск бота, фоновые задачи
├── config.py               — все настройки (токены берутся из .env)
├── database.py              — работа с SQLite (пользователи, логи, платежи,
│                              таблица активных подписок)
├── keyboards.py             — все inline-клавиатуры
├── middlewares.py           — проверка подписки на канал
├── states.py                — состояния FSM для админских диалогов
├── remnawave_client.py      — интеграция с Remnawave API (панель 3.2.3)
├── platega_client.py        — интеграция с Platega (приём оплаты)
├── test_remnawave.py        — тестовый скрипт проверки связи с Remnawave
├── update.sh                — безопасное обновление из GitHub (не трогает БД)
├── .gitignore                — исключает data/ (БД), .env, venv из git
├── handlers/
│   ├── start.py             — /start, реферальный вход, главное меню
│   ├── profile.py           — профиль, баланс, пополнение
│   ├── subscription.py      — статус подписки, покупка тарифов, реферальные бонусы
│   ├── referral.py          — реферальная ссылка и статистика
│   ├── support.py           — поддержка, тикеты, политика/соглашение
│   └── admin.py              — админ-панель, поиск пользователя, тикеты, рассылки
├── requirements.txt
├── .env.example
└── data/bot.db               — создаётся автоматически при первом запуске (в .gitignore)
```
